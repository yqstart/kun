# kun 多平台发布

## 触发方式

推送 `v*` 标签（如 `v0.2.0`）自动触发发布，也可在 Actions 页手动 **Run workflow**：

```bash
git tag v0.2.0
git push origin v0.2.0
```

## 产物

| 平台 | 产物 | 构建方式 |
|---|---|---|
| macOS Apple Silicon | `kun-<版本>-macos-arm64.dmg` | macos-latest（原生 ARM） |
| macOS Intel | `kun-<版本>-macos-x64.dmg` | macos-15-intel（官方 Intel runner） |

- 版本号取自 tag（`v0.2.0` → `0.2.0`）
- Release 正文从 `CHANGELOG.md` 提取对应版本段落
- 若 tag 已存在同名 Release（如手动创建），产物自动挂载；否则自动创建

## 本地预览打包（macOS）

```bash
cargo build --release
./scripts/package-macos.sh 0.2.0 arm64
# 产出 target/release/kun-0.2.0-macos-arm64.dmg 与 kun.app
```

打包脚本逻辑：生成图标（`make-icon.swift`，渐变紫 + K 字母）→ 组装 .app bundle（Info.plist + ad-hoc 签名）→ 组装 dmg（内含 `kun.app` 与 **Applications 快捷方式**，本机打包时自动美化图标布局）→ `hdiutil` 制作 dmg。

## macOS 安装后提示「已损坏」

未公证导致（开源项目未配置 Apple 开发者签名，构建已附 ad-hoc 签名）。解除隔离：

```bash
xattr -cr "/Applications/kun.app"
```

然后右键 → **打开**。

## 平台支持

**仅支持 macOS**（Apple Silicon + Intel）。SSH 库（russh）使用 ring 后端（纯 Rust，无 C 依赖）。

## 自动更新

- 应用启动后自动检查 GitHub Releases 最新版本（`kun-core::updater`，ureq 轻量 HTTP）
- 检查逻辑：请求 `github.com/yqstart/kun/releases.atom`（Atom feed，不受 API 限流影响），解析首个 `<entry>` 取最新 tag，语义化版本比较
- **应用内一键更新**：按当前架构（arm64/x64）构造 dmg 直链下载（进度回调）→ 后台脚本 `hdiutil` 挂载 → 等待主程序退出 → `ditto` 替换安装到 `/Applications/kun.app`（失败回退 `~/Applications`）→ 自动重启
- 手动检查：工具栏「检查更新」按钮

## 维护者侧说明

- 工作流文件：`.github/workflows/release.yml`（发布）、`ci.yml`（push/PR 检查）
- 网络集成测试在 CI 上自动跳过（检测不到测试 sshd）；本地跑集成测试需先 `./scripts/test-sshd.sh start`
- 发布前建议本地过一遍：`cargo test --workspace && cargo clippy --workspace --all-targets -- -D warnings && cargo fmt --all --check`
